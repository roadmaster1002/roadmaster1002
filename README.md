# CHEM² · Market Intelligence

삼양사 화학2그룹 기획 담당자를 위한 경쟁시장 MI 워크스페이스의 첫 버전입니다. 삼양엔씨켐, 삼양KCI, Verdant의 경쟁시장 지도, 관심 주제, 등록 자료 분석과 주간 브리핑을 한 화면에서 다룹니다.

## 실행

Node.js 24와 npm을 권장합니다. 기존 체크아웃에서 작업하면 됩니다.

```sh
cd /workspace/roadmaster1002
npm ci
npm run dev
```

개발 화면은 포트 `5173`, 분석 API는 포트 `3001`에서 실행됩니다. Vite가 `/api` 요청을 API 서버로 전달합니다. 개발 시 두 프로세스가 모두 필요하며 `npm run dev`가 함께 실행합니다.

```sh
npm run build
npm start
```

빌드 후에는 API 서버가 `dist/`의 화면도 포트 `3001`에서 제공합니다. API의 `PORT`를 변경할 수 있습니다. 개발 중 API 포트를 바꾸려면 `vite.config.ts`의 프록시 대상도 맞춰야 합니다.

```sh
npm test
```

기존 서버 테스트는 입력 제한·출처 검증·예시 자료 표시·로컬 분석과 API 주소 검증을 다룹니다. `npm run build`는 TypeScript 검사와 Vite 번들 생성을 실행합니다. 테스트와 빌드는 실제 최신 뉴스의 정확성이나 외부 AI 제공자의 응답을 검증하지 않습니다.

## 사용 흐름

1. 기업 필터로 삼양엔씨켐, 삼양KCI, Verdant 중 검토 범위를 선택합니다.
2. 경쟁시장 지도에서 경쟁사 후보와 제품·응용 분야를 비교합니다. 공정별 기업 배치를 시장점유율이나 실제 공급 계약으로 해석하지 마세요.
3. 신뢰할 수 있는 공식 발표·공시·제품 자료를 확인한 뒤 **자료 등록**에서 제목, 요약, 날짜와 원문 출처를 입력합니다. URL만 등록해 원문을 자동으로 읽는 기능은 없습니다.
4. 관심 신호를 북마크하고, 관심 모니터링에서 조사할 주제를 관리합니다.
5. 분석 도우미에 질문하거나 주간 브리핑 초안을 생성합니다. 제시된 근거 ID와 원문을 확인한 후 회의 안건으로 사용합니다.
6. 브리핑을 Markdown으로 내려받거나, 워크스페이스 설정에서 JSON 백업을 내려받습니다.

## 데이터와 근거

- 기본 신호 **9건은 모두 가상 예시 시나리오**입니다. 실제 최신 뉴스나 실제 투자·제품 발표를 수집한 데이터가 아닙니다. 표시 날짜 역시 예시 데이터의 일부입니다.
- 예시 신호의 링크는 기업 홈페이지 참고 링크이며, 시나리오가 실제 발생했다는 근거가 아닙니다.
- 산업 지도에는 반도체·전자재료 8단계, 퍼스널케어 원료 7단계, 계면활성제·스페셜티 7단계가 있습니다. 장비·소재 기업을 구분하고 자사 위치를 강조합니다. 기업 카드에서 역할·일반 수익 구조·조사 항목을, 공정에서 투입·변환·결과를 탐색할 수 있습니다. 별도의 기본 경쟁사 목록은 12개 기업의 13개 사업별 항목이며 Evonik은 두 사업에 포함됩니다. 분류는 실제 납품·경쟁 강도·점유율을 확정하지 않습니다.
- 기업 설명과 홈페이지 주소는 초기 조사 후보 데이터입니다. 실제 업무에 사용하기 전에 현재 회사 정보와 제품별 직접 경쟁 관계를 확인해야 합니다.
- 사용자 등록 자료도 자동 검증하지 않습니다. 원문 확인, 발표일, 제품·지역 범위와 사실·가설 구분은 분석 담당자가 검토해야 합니다.

참고 사이트 `https://maknae.ai.kr/report/map`의 직접 접근은 환경 정책에서 차단됐지만, 사용자가 제공한 화면을 기준으로 공정 흐름·상단 장비/하단 소재·기업 역할·수익 구조 탐색을 구현했습니다. 산업 내 역할은 초기 조사 분류이며 실제 거래 관계를 의미하지 않습니다.

## 분석 모드와 AI 연결

기본값은 **로컬 분석 모드**입니다. API 키 없이 등록 문장, 질문 키워드와 규칙으로 자료를 골라 관찰·기획 시사점·후속 확인 과제를 구성합니다. 외부 조사나 생성형 AI 추론을 수행하지 않습니다.

생성형 AI를 사용하려면 서버 프로세스에 다음 환경변수를 주입하고 재시작합니다.

| 변수 | 용도 |
| --- | --- |
| `MI_LLM_API_KEY` | 선택 사항. 값이 있으면 OpenAI 호환 Chat Completions API 모드를 사용합니다. |
| `MI_LLM_BASE_URL` | 기본값 `https://api.openai.com/v1`. 인증정보 없는 공개 HTTPS API 주소만 허용합니다. |
| `MI_LLM_MODEL` | 기본값 `gpt-4.1-mini`. 제공자가 지원하는 모델로 설정합니다. |
| `PORT` | API·운영 화면 포트. 기본값 `3001`. |

키는 서버 환경 설정이나 비밀 저장소에서 관리합니다. 브라우저 코드, `VITE_` 변수, 저장소, 자료 본문에 넣지 마세요. 이 프로젝트는 `.env`를 자동 로드하지 않습니다. 로컬에서 `.env.example`을 복사해 사용한다면 Node.js의 명시적 로드 기능을 사용합니다. `.env`는 Git 제외 대상입니다.

```sh
cp .env.example .env
# .env를 로컬 편집기로 수정한 후 실행
node --env-file=.env --run dev
# 운영 빌드를 만든 뒤 실행할 때
node --env-file=.env --run start
```

**LLM 모드에서는 질문과 선택된 근거 자료가 설정된 외부 제공자에게 전송됩니다.** 자료 전송 권한과 제공자 정책을 확인하세요. API 키는 서버에서만 사용합니다. 외부 API 이용에는 제공자 인증, 요금과 해당 목적지의 네트워크 허용이 필요합니다. 서버는 상속된 `HTTPS_PROXY`를 사용하며 TLS 검증을 유지합니다. 인증·네트워크 실패는 오류로 표시하며, 외부 API 성공으로 가장하지 않습니다. 키를 설정하지 않은 로컬 모드는 외부 AI API에 자료를 전송하지 않습니다.

## 보관과 범위

자료, 북마크, 관심 주제와 생성한 브리핑은 **현재 브라우저의 localStorage**에 저장됩니다. 서버 데이터베이스나 팀 공유 저장소가 없습니다. 다른 브라우저·기기에서 자동으로 이어지지 않으며 브라우저 데이터 삭제 시 사라질 수 있습니다. JSON 백업은 내려받을 수 있지만 현재 화면에는 백업 가져오기 기능이 없습니다.

분석 API는 요청당 최대 **40건**, JSON 본문 **2MB**를 허용하며 각 요약은 **4,000자**까지 받습니다. 브리핑은 선택 기간에 해당하는 전달 자료 최대 40건, 질문 분석은 최근 40건 중 최대 6건을 골라 처리합니다. 화면에 실제 검토 건수를 표시하며, 전체 저장 자료를 모두 분석했다는 의미는 아닙니다.

현재 버전에는 실시간 뉴스 자동 수집, 예약 실행, 이메일·메신저 발송, 로그인·권한 관리, 팀 공유 저장소, 가격·시장점유율 데이터 공급이 포함되지 않습니다. 관심 모니터링은 조사 주제의 관리 기능이며, 백그라운드 수집기가 아닙니다. 공개 서비스로 운영하기 전에는 인증과 저장소를 연결해야 합니다.

## GitHub Pages로 열기

GitHub Pages는 정적 파일만 제공하므로 API 서버가 실행되지 않습니다. `npm run build:pages`는 원문 등록·북마크·관심 주제·로컬 분석·브리핑을 **브라우저 안에서** 처리하는 별도 배포물을 `dist-pages/`에 만듭니다. 기본 경로는 `/roadmaster1002/`이며 이 이름의 저장소를 대상으로 합니다. 비밀값과 서버 코드는 배포하지 않습니다.

```sh
npm ci
npm run build:pages
# 원격 gh-pages 브랜치에 정적 배포물을 올립니다. Git 쓰기 권한 필요
node scripts/publish-pages.mjs
```

저장소 관리자는 GitHub의 **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: gh-pages / (root) → Save**를 한 번 설정해야 합니다. 그 뒤 GitHub가 배포한 주소는 `https://roadmaster1002.github.io/roadmaster1002/`입니다. 이 주소는 예상 배포 주소이며 실제 배포 완료 여부는 GitHub Pages 화면과 HTTP 응답으로 확인해야 합니다. 클라우드 내부에서 서버를 시작하거나 환경 스냅샷을 게시하는 것만으로 이 웹주소가 열리지는 않습니다.

`npm run deploy:pages`는 빌드와 gh-pages 갱신을 함께 수행합니다. 임시 Git 인덱스를 사용하며 현재 체크아웃이나 사용자 변경을 초기화하지 않습니다. 기존 배포 커밋을 부모로 유지하고 강제 푸시하지 않습니다. 다른 저장소에 배포하려면 Vite base와 배포 스크립트의 목적지를 먼저 수정하세요.

Pages에 배포된 버전은 **로컬 분석 전용**이며 외부 AI API 키를 웹사이트에 넣으면 안 됩니다. 생성형 AI 연결은 서버 버전에서 별도로 구성해야 합니다. 브라우저별 자료는 기기 간 공유되지 않습니다.

### 설치 없이 파일로 열기

`npm run build:offline`은 `dist-offline/index.html`에 스크립트·스타일·글꼴을 모두 포함한 파일을 만듭니다. 이 파일을 내려받아 Chrome/Edge 등에서 열면 서버 없이 산업 지도와 로컬 분석을 사용할 수 있습니다. `file:` URL에서 브라우저가 저장소를 제한하면 저장 경고가 표시되므로 백업 파일을 내려받으세요.

### 정적 배포 검증

`dist-pages/`를 `/roadmaster1002/` 아래에 제공하는 로컬 정적 서버를 실행한 후 `npm run test:static`을 사용합니다. 기본 검사 주소는 `http://127.0.0.1:4173/roadmaster1002/`이며 `BASE_URL`로 바꿀 수 있습니다. API 호출 없이 자료 등록·분석·브리핑·다운로드가 되는지와 산업 지도 탐색을 실제 Chromium으로 확인합니다.

## 큰 글씨와 심층 MI

가독성 모드는 일반 본문16–17px·시장 신호 제목21px·출처14px를 기본으로 사용하며, 심층 MI 카드·리딩 본문은18px로 표시합니다. 산업 지도 공정 구성은 유지하고 기업명17px·설명14px로 키웠으며, 좁은 화면에서는 지도 영역만 좌우로 이동합니다.

마켓 인텔리전스는 **심층 리딩 후보 / 등록한 기사 / 기능 예시**로 구분합니다. ASML·BASF 연차보고서, Canon 기술 발표, EU 규제 등9건은 초기 조사 원문 후보이며 실제 기사 수집 결과가 아닙니다. 모든 후보에 원문 미검증을 표시하며, 리딩 가이드는 원문 발췌·요약이 아닌 기획팀의 검토 질문입니다. 역사적 문서는 최신 개정·폐지·대체 여부를 확인해야 합니다. 기존9개 가상 신호는 기능 예시 탭에서 볼 수 있습니다.

실제 기사에는 본문 또는 요약 외에 **핵심 논점 / 근거·수치·조건 / 사업 영향(담당자 분석) / 후속 조사**를 등록할 수 있습니다. 이 노트는 브라우저에 보관되며, 분석·브리핑의 시사점 입력과 라이브러리 내보내기에 반영됩니다. 다른 팀원에게 자동 전송하지 않습니다.

```sh
# 실제 접근 가능한 공개 기사 URL을 지정합니다.
node scripts/collect-article.mjs --url 'https://semiengineering.com/실제-기사-경로/' --company ncchem --out /tmp/article.json
```

`--url`은 예시 문자열을 실제 기사 주소로 바꿔야 합니다. 수집기는 지정한10개 발행처의 HTTPS HTML만 처리하고 유료벽·로그인 제한을 우회하지 않습니다. 프록시·TLS 검증을 유지하며 본문·출처·발행일·수집 시각·본문 해시를 저장합니다. 발표일을 찾지 못하면 `null`로 남기며 수집일을 발표일로 대체하지 않습니다. PDF·일부 JavaScript 페이지는 수동 등록이 필요합니다.

생성한 `chem2.article.v1` JSON은 화면의 **기사 JSON 가져오기**에서 불러옵니다. 원문 앞4,000자를 요약/내용 칸에 넣고 전체 수집 발췌문(최대12,000자)을 함께 보관합니다. 발표일이 비어 있으면 원문에서 확인해야 등록할 수 있습니다. `source-read`는 본문 수집 이력이며 사실 검증 완료가 아닙니다. 수집 파일과 등록 자료를 신뢰할 때도 원문과 주장의 근거를 별도로 확인해야 합니다.

이번 작업에서는 출판사·규제 사이트에 대한 실행 환경 접근이 HTTP403으로 차단되어 실제 기사 원문을 수집하지 못했습니다. 필요한 도메인을 환경 설정 초안에 추가했습니다. 설정을 저장·적용한 후에 원문 수집을 실행해야 합니다. 과거 문서 제목·연도를 현재 뉴스나 원문 검증 완료로 표시하면 안 됩니다.

`npm test`는 기존 분석 로직12개와 기사 수집기9개를 실행합니다. 원문 수집기 테스트는 로컬 HTML 및 응답 fixture를 사용하며 외부 기사 수집 성공을 의미하지 않습니다.

## 최신 뉴스와 주간 브리핑 v2

MI 첫 화면은 **최신 뉴스**이며 기본 발행 기간은 최근7일입니다. 최근30·90일로 넓힐 수 있고, 2023·2024년 문서는 **배경 리딩**으로 분리합니다. 발행일 미확인·미래 날짜·기능 예시는 최신 기사 수를 채우는 데 사용하지 않습니다. 해당 기간 자료가 없으면0건으로 표시하며 시장 변화가 없다고 결론 내리지 않습니다.

### 공개 RSS 갱신

`.github/workflows/refresh-news.yml`은 한국시간 매일08:00에 Google News 검색 RSS3개(사업별 키워드)를 수집하고 `public/latest-news.json`만 갱신합니다. 수동 실행과 수집기/워크플로 변경 푸시로도 실행할 수 있습니다. GitHub 저장소의 Actions 실행 및 workflow 쓰기 권한이 필요합니다. **워크플로를 추가했다고 실제 수집 성공이 검증된 것은 아니며**, 첫 실행 결과는 Actions에서 확인해야 합니다.

수집 데이터는 공개 제목·발행처·피드 발행일·링크·RSS 설명 메타데이터입니다. 기사 본문 열람·사실 검증·영향도 평가를 수행하지 않습니다. 사업 및 유형 분류도 키워드 기준입니다. 중복·명백한 시장규모/CAGR 광고성 보고서 제목을 걸러 최대60건(사업별30건)·최근90일을 보관합니다. 모든 출처 수집이 실패하면 이전 자료와 마지막 성공 시각을 보존하고, 시도 시각과 실패 상태만 기록합니다. 일부 실패는 별도 표시합니다.

운영 GitHub Pages 화면은 공개 저장소의 원본 스냅샷을 읽으므로 뉴스 갱신마다 사이트 빌드를 다시 할 필요가 없습니다. **브라우저의 개인 기사·분석 노트·브리핑은 자동 수집 작업이나 GitHub로 전송하지 않습니다.** 로컬 서버는 같은 경로의 JSON을, 오프라인 HTML은 포함된 자료와 브라우저 캐시를 사용합니다. 마지막 수집 성공과 기사 발행일은 구분해서 표시합니다. 자동 수집은 공개 RSS 갱신 기능이며 유료 기사 본문이나 로그인 제한을 우회하지 않습니다.

```sh
npm run refresh:news
```

위 명령은 실행 환경에서 해당 RSS 목적지 접근이 허용될 때만 실제 수집할 수 있습니다. 이 클라우드 인스턴스의 제한을 다른 서비스로 우회해 원문을 읽는 용도로 사용하면 안 됩니다. 수집기 테스트는 모의 응답으로 실행하며 실제 뉴스나 현재 기사 수를 증명하지 않습니다.

### 주간 브리핑 강화

- 최근7일·이번주·지난주·직접 지정 기간, 사업 범위, 검토 자료 선택
- 기본값은 기능 예시 제외. 뉴스 메타데이터와 원문 등록 자료의 근거 수준 구분
- 핵심 요약, 우선 검토5건, 동일 길이 직전 기간 기록 비교
- 삼양엔씨켐·삼양KCI·Verdant별 관찰·검토 사항과 자료 공백
- 원문 ID·URL에 연결한 후속 액션, 담당·기한·상태와 회의 메모 편집
- Markdown, 액션 CSV(근거 URL 포함), 인쇄/PDF
- 새 형식 최근20개 브리핑을 `chem2-weekly-v2`로 로컬 보관. 기존 `chem2-briefs-v1` 자료는 변경하지 않고 읽기 전용으로 내려받을 수 있음

전기 자료가 없으면 ‘비교 불가’로 표시합니다. ‘신규/지속’은 등록된 제목·URL 기록 대조이며, 실제 시장 이벤트의 신규성이나 주간 성장률을 의미하지 않습니다. 원문 자료가 없으면 자료 공백 보고서만 만들며 시장 사실·수치·담당자·기한을 지어내지 않습니다. 주간 브리핑은 입력 근거를 구조화하는 로컬 기능이며 생성형AI 추론을 수행하지 않습니다.

`npm run test:news`는 최신성 필터·실패 시 보존·전기 비교·액션 편집/저장·내보내기를 모의 뉴스 스냅샷으로 확인합니다. 실제 기사나 운영 자동 수집 검증과 구분해야 합니다.
